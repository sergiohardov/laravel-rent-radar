## Проверка 2026-10-04

Одноразовый `check.php`, загруженный через File Manager в cPanel и открытый в браузере. Делает те же запросы, что будет делать бот: PHP curl, HTTP/1.1, `User-Agent: GuzzleHttp/7`. SSH в cPanel нет: пункт «SSH Access» не показывается, по справке nic.ua его открывает поддержка.

### Площадки с IP хостинга

Исходящий IP — `95.216.242.245`, AS24940 Hetzner Online, Финляндия.

| Площадка | С хостинга | С украинского домашнего IP |
|---|---|---|
| ЛУН `flatfy.ua/api/realties` | **403**, проверка Cloudflare «Just a moment…» | 200 |
| OLX `olx.ua/api/v1/offers/` | **403** от CloudFront и по HTTP/1.1, и по HTTP/2 | 200 по HTTP/1.1, 403 по HTTP/2 |
| DIM.RIA `searchEngine` + `realty/data` | 200 | 200 |

Чтобы понять причину блокировки, ЛУН и OLX проверили через Scrape.do (бесплатный план) с украинских IP разных типов:

| Тип IP | Сеть | ЛУН | OLX |
|---|---|---|---|
| Дата-центр, UA | AS200525 Hosting Ukraine LTD | 200 | 200 |
| Домашний, UA | AS15713 Global-City-Net | 200 | 200 |

Украинский IP дата-центра проходит, значит, блокируют по стране или конкретно сеть Hetzner, а не любые дата-центры.

**Решение (2026-10-04):** хостинг nic.ua остаётся. ЛУН и OLX ходят через украинский прокси дата-центра (порядка $1–3 в месяц), DIM.RIA — напрямую. Прокси покупаем перед деплоем (пункт 29) и подтверждаем с хостинга через `check.php`. Оговорка: Scrape.do мог повторять запросы и подставлять свои заголовки, поэтому окончательная проверка — с купленным прокси.

Мелочи при входе: OpenSSH сервера без постквантового обмена ключами (предупреждение клиента, на работу не влияет); `perl: warning: Setting locale failed` — Mac передаёт `LC_CTYPE=UTF-8`, которого нет на сервере; лечится строкой `SetEnv LC_ALL=C.UTF-8` для этого хоста в `~/.ssh/config`.

### ЛУН и OLX через Scrape.do (пункт 29)

**Исходящие порты хостинга:** открыты 80 и 443, закрыты 8080 и 3128 (`Connection refused` до `portquiz.net` и `proxy.scrape.do:8080`). Поэтому режим прокси Scrape.do (порт 8080) с хостинга не работает, как и обычные прокси дата-центра на нестандартных портах. Работает режим API: `SOURCES_PROXY_URL="https://api.scrape.do/?token=ТОКЕН&geoCode=ua"`, запрос уходит на `api.scrape.do` по 443 с адресом площадки в параметре `url`, заголовки браузера Scrape.do подставляет сам.

Проверено из dev через наш код 2026-10-04:

| | Прокси, 8080 | API, 443 |
|---|---|---|
| ЛУН | без `customHeaders=false` нет ответа и за 50 с (Scrape.do пересылает наш `User-Agent: GuzzleHttp/7`, Cloudflare его не пускает); с ним — 200, ~15 с на страницу | 200, запуск 9,4 с |
| OLX | 200, 6–26 с на страницу | 200, запуск 7,1 с |

С хостинга по SSH (`curl` в режим API, 2026-10-04): ЛУН — 200 за 12,9 с, OLX — 200 за 8,3 с.

Поддомен `rentradar.creastep.com`: корень — `~/rentradar.creastep.com/public`, SSL включён (AutoSSL). База PostgreSQL и пользователь созданы в cPanel.

Токен оказывается в адресе запроса: в последней ошибке источника (база, алерты, вывод команд) он маскируется (`SourceHttp::redact`). Обычный запуск — одна страница, ~380 запросов в сутки на две площадки: бесплатных 1 000 в месяц хватит на ~2,5 дня.

Чего не позволяет PostgreSQL 10 и чего в коде быть не должно: генерируемые колонки (12+), `INCLUDE` в индексах (11+), процедуры (11+), встроенный `gen_random_uuid()` (13+), `MERGE` (15+).
